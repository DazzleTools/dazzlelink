# Human Test Checklist: dazzlelink 0.11.0 -- multi-target selection

**Target version:** 0.11.0
**Ships with commit:** `46e0675` feat: multi-target dazzlelinks -- locality selection at execute (0.11.0); release head `2488f30` (the Amendment-4 monopole reshape + help/association fixes ride the same tag)
**Companion automated tests:** dazzlelink 80 (`tests/test_multi_target.py` +22 new), dazzle-linklib 108 (`tests/test_locality_selection.py` +19, shipped in linklib 0.4.0/0.5.0).

## What this is

0.11.0 delivers issue #25: one `.dazzlelink` record carries a local path AND a web URL, replacing the `.dazzlelink` + `.url` file pair. The user CHOOSES which copy opens via a rung on the locality ladder (`--prefer` / `--only` / `--kind` / `--target N`), and `--mode info` lists every target numbered with its rung plus a "Would open" preview computed with zero network I/O. This checklist covers what the mocks can't: **really opening a URL through the OS handler** (`os.startfile` / `xdg-open` launch a browser in the tests' place), the info render's readability in a real terminal, help-epilog rendering, and double-click behavior on records carrying URLs.

## Legend (shorthand used below)

| Code | Meaning |
|---|---|
| AC-n | Acceptance check n from the #25 design (mirrored by a named automated test in `tests/test_multi_target.py`) |
| rung / reach | A named step on the locality ladder (`local` 0, `intranet` -1, `internet` -2 — possession at the rest seat, each step outward one degree of removal) / an alias for one (`local-network`, `remote`; scheme aliases `http`/`https`/`url` → internet). Any OTHER spelling selects a locator KIND directly (open-ended: `ftp`, `gopher`, ...) |

## Prerequisites

1. Machine with the stack installed: `pip install dazzlelink` (>= 0.11.0) pulling `dazzle-linklib` >= 0.4.0 -- or editable installs.
2. A default browser you don't mind opening `https://example.org/...` in (the URL-opening tests really open it).
3. State isolation: work only in a scratch directory.

### Reset between sections

  **cmd.exe**: `rmdir /s /q %TEMP%\dz11 & mkdir %TEMP%\dz11 & cd /d %TEMP%\dz11`
  **PowerShell**: `Remove-Item -Recurse -Force $env:TEMP\dz11 -ErrorAction SilentlyContinue; New-Item -ItemType Directory $env:TEMP\dz11 | Out-Null; Set-Location $env:TEMP\dz11`
  **POSIX**: `rm -rf /tmp/dz11 && mkdir /tmp/dz11 && cd /tmp/dz11`

Seed a scratch target (all shells, from inside the scratch dir):

  ```
  python -c "open('r.pdf','w').write('hello')"
  ```

## High-Value Verification (~5 minutes)

**If you only have 5 minutes**, run these 5 tests.

### HV.1 -- Both suites green

- [ ] **Steps:** `python -m pytest -q --no-cov` in `C:\code\dazzlelink`; `python -m pytest -q` in `C:\code\dazzle-linklib`.
- [ ] **Expected:** 80 / 108 passed (skips for privilege-gated tests are fine).
- [ ] **Why this matters:** the regression floor -- 58 pre-existing dazzlelink tests must not have moved.

### HV.2 -- One record, two targets, numbered info (AC-5, AC-8)

- [ ] **Steps** (cross-shell, from the scratch dir):

  ```
  dazzlelink create --also-url https://example.org/r.pdf r.pdf r.pdf.dazzlelink
  dazzlelink execute --mode info r.pdf.dazzlelink
  ```
- [ ] **Expected:** a `Targets (3):` block listing `[0] path ... rung: local`, `[1] relative ... rung: local`, `[2] url ... rung: internet https://example.org/r.pdf`, then `Would open: [0] <the local path>` and the closing select-hint line.
- [ ] **Why this matters:** this is the feature -- one record carrying both copies, enumerated in the `--target` address space. If the url locator is missing, `--also-url` never landed.

### HV.3 -- Local wins, URL is the fallback (AC-1)

- [ ] **Steps:** `dazzlelink execute --mode open r.pdf.dazzlelink` (opens the local file); then delete `r.pdf` (**cmd**: `del r.pdf` / **PS**: `Remove-Item r.pdf` / **POSIX**: `rm r.pdf`) and run the same execute again.
- [ ] **Expected:** first run opens the local file in its handler app; second run opens `https://example.org/r.pdf` in the default browser. No error either time.
- [ ] **Why this matters:** offline-first with web fallback is #25's headline behavior, and the real `os.startfile`-on-URL hop is exactly what the mocks replace.

### HV.4 -- Preference beats presence (AC-10)

- [ ] **Steps:** re-seed `r.pdf` (see Prerequisites), then `dazzlelink execute --mode open --prefer remote r.pdf.dazzlelink`.
- [ ] **Expected:** the browser opens the URL **even though the local file exists**.
- [ ] **Why this matters:** CHOICE is the design's soul -- `--prefer` must reorder, not merely fall back.

### HV.5 -- The ladder is in the help (AC-14)

- [ ] **Steps:** `dazzlelink execute --help`
- [ ] **Expected:** an epilog block "locality ladder" listing the three rungs (`local +0`, `intranet -1`, `internet -2`), the reach aliases, the scheme aliases, and the open-ended KIND sentence. Columns aligned in your terminal.
- [ ] **Why this matters:** the help is derived from the library's axis at runtime; a rendering or import problem here breaks every `execute --help` invocation.

## Section 1: create --also-url (~5 min)

### 1.1 Repeatable flag records multiple URLs (AC-8)

- [ ] **Steps** (from a re-seeded scratch dir):

  ```
  dazzlelink create --also-url https://example.org/r.pdf --also-url https://mirror.example.net/r.pdf r.pdf r2.dazzlelink
  python -m json.tool r2.dazzlelink
  ```
- [ ] **Expected:** `link.locators` holds both url entries in the order given; `link.target_representations` still carries `original_path` + `relative_path` (the path family is untouched).

### 1.2 Malformed URL fails at create, not at open

- [ ] **Steps:** `dazzlelink create --also-url notaurl r.pdf bad.dazzlelink`
- [ ] **Expected:** exit code 1, `ERROR: --also-url expects scheme-form URLs (e.g. https://host/file): notaurl` on stderr, and **no** `bad.dazzlelink` file created.
- [ ] **Check exit code:** **cmd**: `echo %ERRORLEVEL%` / **PS**: `$LASTEXITCODE` / **POSIX**: `echo $?`

### 1.3 Executable (polyglot) records carry the URL too

- [ ] **Steps:** `dazzlelink create --executable --also-url https://example.org/r.pdf r.pdf rx.dazzlelink`, then `dazzlelink execute --mode info rx.dazzlelink`.
- [ ] **Expected:** the script-wrapped record still lists the url locator in `Targets (3):` -- the locators ride inside the embedded JSON.

## Section 2: execute selectors (~10 min)

### 2.1 --only restricts; a miss names what the record has (AC-11)

- [ ] **Steps:** `dazzlelink execute --mode open --only local-network r.pdf.dazzlelink`
- [ ] **Expected:** exit 1 with `no locators match the selection (--only local-network); this record has: local (path, relative); remote (url)`. Nothing opens. Read the message as a user: does it tell you your next command?

### 2.2 --only remote opens the URL

- [ ] **Steps:** `dazzlelink execute --mode open --only remote r.pdf.dazzlelink`
- [ ] **Expected:** browser opens the URL (local file present but excluded by the filter).

### 2.3 --kind url forces the URL; --kind miss errors cleanly (AC-3)

- [ ] **Steps:** `dazzlelink execute --mode open --kind url r.pdf.dazzlelink`, then `dazzlelink execute --mode open --kind ipfs r.pdf.dazzlelink`
- [ ] **Expected:** first opens the URL; second exits 1 naming `--kind ipfs` and the available reaches/kinds.

### 2.4 --target N pins exactly; out-of-range names the range (AC-4)

- [ ] **Steps:** `dazzlelink execute --mode open --target 2 r.pdf.dazzlelink`, then `--target 9` on the same record.
- [ ] **Expected:** `--target 2` opens the URL (`[2]` per info); `--target 9` exits 1 with `--target 9 is out of range: this record has 3 locator(s), valid indices 0..2`.

### 2.5 Pin + selector conflict names ALL offenders (AC-15)

- [ ] **Steps:** `dazzlelink execute --target 1 --prefer remote --kind url r.pdf.dazzlelink`
- [ ] **Expected:** exit 1; the error names **both** `--prefer` and `--kind`, and ends with `(nothing was opened)`.

### 2.6 Open-ended spellings: kind fallthrough, record as validator

- [ ] **Steps:** `dazzlelink execute --mode open --only gopher r.pdf.dazzlelink`, then `dazzlelink execute --mode open --prefer gopher r.pdf.dazzlelink`
- [ ] **Expected:** `--only gopher` exits 1 with the no-match error naming the reaches/kinds the record HAS (there is no closed vocabulary — `gopher` is treated as a kind); `--prefer gopher` opens the LOCAL file (a preference never filters — nothing matched, everything stayed fallback).

### 2.7 --prefer is a preference, not a filter

- [ ] **Steps:** delete the URL from reachability's view by using a path-only record: `dazzlelink create r.pdf plain.dazzlelink`, then `dazzlelink execute --mode open --prefer remote plain.dazzlelink`
- [ ] **Expected:** the LOCAL file opens -- nothing remote exists, and preference never turns into a filter.

## Section 3: info render + double-click (~5 min)

### 3.1 Zero network I/O in info (AC-5)

- [ ] **Steps:** disconnect from the network (Wi-Fi off / unplug), then `dazzlelink execute --mode info r.pdf.dazzlelink`.
- [ ] **Expected:** instant, complete output -- the url row and the Would-open preview render with no delay, no timeout, no error. Reconnect afterwards.

### 3.2 Info render readability (human judgment)

- [ ] **Steps:** rerun `--mode info` in your normal terminal (and once in a narrow ~80-col window).
- [ ] **Expected:** the `[N] kind rung: X value` columns stay readable; long URLS/paths wrap without corrupting the table; no mojibake on Windows codepages (output is plain ASCII).

### 3.3 Double-click / no-flag execute is unchanged (mode precedence)

- [ ] **Steps (Windows):** double-click `r.pdf.dazzlelink` in Explorer (with the file association installed), or run `dazzlelink execute r.pdf.dazzlelink` with no flags.
- [ ] **Expected:** identical to 0.10.0 behavior -- the record's embedded `default_mode` governs (info by default). No selector is ever implied; selection is CLI-only, never stored.

### 3.4 url-only record (the .url replacement, AC-2)

- [ ] **Steps:**

  ```
  python -c "import json; json.dump({'link': {'locators': [{'kind':'url','value':'https://example.org/only.pdf'}]}}, open('urlonly.dazzlelink','w'))"
  dazzlelink execute --mode info urlonly.dazzlelink
  dazzlelink execute --mode open urlonly.dazzlelink
  ```
- [ ] **Expected:** info shows `Targets (1):` with only the url (no Target/Target-Details blocks, no crash); open launches the browser.

## Section 4: cross-version grace (~3 min)

### 4.1 A 0.10.0 reader ignores the url locator (AC-7)

- [ ] **Steps:** in a venv with `dazzlelink==0.10.0`, run `dazzlelink execute --mode info r.pdf.dazzlelink` and `--mode open` (local file present).
- [ ] **Expected:** no crash; the local file opens; the url locator is silently ignored. Skip if you don't keep a 0.10.0 venv around -- the automated `test_old_reader_grace_two_target_record` pins the call shape.

### 4.2 Round-trip through an old tool preserves locators

- [ ] **Steps:** still in the 0.10.0 venv, `dazzlelink rebase %TEMP%\dz11` (**PS**: `dazzlelink rebase $env:TEMP\dz11` / **POSIX**: `dazzlelink rebase /tmp/dz11`), then back in 0.11.0: `python -m json.tool r.pdf.dazzlelink`.
- [ ] **Expected:** `link.locators` still carries the url entries byte-identical.

## What the automated tests DON'T cover

- **Really opening a URL** through `os.startfile` (Windows) / `xdg-open` (POSIX) -- the mocks capture the value instead of launching; browser choice, protocol-handler config, and spaces-in-URL behavior are real-machine facts (HV.3, HV.4, 2.2-2.4).
- **Offline behavior with real network state down** (3.1) -- the automated no-network proof monkeypatches sockets; pulling the plug is the honest version.
- **Terminal rendering** of the info table and the help epilog across cmd/PowerShell/bash and narrow windows (HV.5, 3.2).
- **Explorer double-click** through the real file association (3.3).
- **A real 0.10.0 install** reading 0.11.0 records (4.1/4.2 use a real old venv; the automated test simulates the old call shape only).
- **Error message quality as felt** -- the tests assert substrings; a human judges whether the no-match message actually tells you your next command (2.1).
