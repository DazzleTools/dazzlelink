# Human Test Checklist: v0.8.0 Release Gate -- Full Regression

**Target version:** 0.8.0 (first PyPI release candidate)
**Ships with commit:** the v0.8.0 milestone (parity complete + monolith deprecated + BOM tolerance)
**Companion automated tests:** 40 across `tests/test_executable_and_mode_precedence.py` (10), `tests/test_cli_commands.py` (19), `tests/test_rebase_dazzlelinks_and_info.py` (6), `tests/test_version.py` (5)

## What this is

The release gate run before cutting the first PyPI release. It is a **full regression** across
everything that landed in the monolith-vs-modular parity arc (v0.7.2-v0.8.0), plus a fresh-venv
install and a packaging audit. The goal: confirm the installable package is a complete, correct,
non-dangerous replacement for the monolith before it goes public.

Per-feature detail lives in the earlier checklists (referenced below); this one is the integration +
regression sweep that ties them together at the release boundary.

## Prerequisites

1. Windows 10/11 (primary) or Linux/macOS, Python >= 3.10.
2. `pip install build` available; ability to make a venv.
3. **State isolation -- non-negotiable:** every file/link/rebase op happens in a `%TEMP%`/`/tmp`
   sandbox. Never touch real projects, real links, or the real `~/.dazzlelinkrc.json`.
4. **NO GUI:** never run `execute` in open/auto mode against a launchable target (it spawns the
   default app). Use `--mode info` only, or verify the open *decision* via a mocked `os.startfile`.
   NEVER double-click / shell-run an executable `.dazzlelink` (fork-bomb surface -- see HV.3).
5. **Symlink privilege:** symlink steps are flagged `[needs privilege]`; SKIP if unavailable.

**Sandbox (PowerShell):**
```powershell
$env:DLT = "$env:TEMP\dl-rg"
Remove-Item -Recurse -Force $env:DLT -ErrorAction SilentlyContinue
New-Item -ItemType Directory -Force "$env:DLT\src", "$env:DLT\dst" | Out-Null
"payload-content" | Set-Content "$env:DLT\src\target.txt"
cd C:\code\dazzlelink
```

## High-Value Verification -- the release gate (~10 min)

### HV.1 -- Build + fresh-venv install + console script
- [ ] `python -m build` produces `dazzlelink-0.8.0` wheel + sdist; `twine check dist/*` PASSES both.
- [ ] In a fresh venv: `pip install <the wheel>`; then `python -c "import dazzlelink, dazzlelink.operations; print(dazzlelink.__version__)"`, `dazzlelink --version` (PEP 440 `0.8.0`), `dazzlelink --help` lists all 12 commands.
- [ ] **Why:** this is the actual PyPI consumer experience; a broken wheel is the worst release bug.

### HV.2 -- Executable generation produces a script that RUNS (not a crash, not a fork bomb)
- [ ] `dazzlelink create <DLT>/src/target.txt <DLT>/e.dazzlelink --executable --mode open`; then
  `python -m py_compile <DLT>/e.dazzlelink` (parses), and `python <DLT>/e.dazzlelink --info` (runs, rc 0).
- [ ] **Why:** regression for the #18 AttributeError + the `\U`/json/JSON-as-code bugs.

### HV.3 -- execute of an executable .dazzlelink does NOT fork-bomb
- [ ] Snapshot `(Get-Process python,pythonw).Count`; run `dazzlelink execute --mode info <DLT>/e.dazzlelink` (timeout 15s); snapshot again. Process count must NOT climb; returns in <2s.
- [ ] **Why:** the critical fork-bomb regression (execute used to shell-run the file via the association).

### HV.4 -- Mode precedence: CLI > file > global
- [ ] A file created `--mode open`, executed with no `--mode`, opens (verify via mocked startfile, NO GUI); executed with `--mode info`, previews. (file beats global; CLI beats file.)

### HV.5 -- The two restored commands work
- [ ] `dazzlelink copy <real symlink> <DLT>/dst` `[needs privilege]` copies it; `dazzlelink update-config <DLT> --mode open --dry-run` then real run mutates `.dazzlelink` files (dry-run does not).

### HV.6 -- rebase fixes .dazzlelink files (both passes) + idempotent
- [ ] Create a `.dazzlelink` in a nested dir, move it shallower (stale relative), `dazzlelink rebase <dir>` -> "1 changed"; run again -> "0 changed". The "Rebasing N dazzlelink file(s)..." pass appears (proves both passes run).

### HV.7 -- richer info + BOM tolerance + exit codes + deprecation
- [ ] `execute --mode info` shows Relative Path + live Size/Type/Exists.
- [ ] Re-save a `.dazzlelink` with a UTF-8 BOM (`Set-Content -Encoding UTF8`); `execute --mode info` still parses.
- [ ] A failing command (`copy <non-symlink> dst`) exits non-zero; a successful one exits 0.
- [ ] `python legacy/dazzlelink_monolith.py --help` prints `DEPRECATION` to stderr but still shows usage.

## Section 1: Full command sweep (~5 min)
- [ ] For each of `create, export, import, scan, convert, mirror, execute, config, check, rebase, copy, update-config`: `--help` is rc 0. Run a benign invocation of each in the sandbox (`scan <DLT>`, `check <DLT>`, `config --view`, `create ...`, etc.) and confirm no crash / sensible output. `convert`/`mirror`/`export` need a real symlink `[needs privilege]`.

## Section 2: Packaging audit (~3 min)
- [ ] Wheel contains `dazzlelink/operations/*.py` (no `src/` prefix); no `legacy/` in wheel or sdist.
- [ ] sdist excludes `scripts/repokit-common`, `private/`, `__pycache__`.
- [ ] `pip show dazzlelink` reports clean `0.8.0`; pywin32 is a dependency on Windows.

## Section 3: Known-bug regressions (~3 min)
Confirm each previously-fixed bug stays fixed (most are covered above; this is the explicit list):
- [ ] #18 AttributeError on `create --executable` -- gone (HV.2)
- [ ] `json`/`stat` NameErrors (links.py/batch.py; POSIX chmod) -- `update_config_batch` imports; executable gen runs on a `Users\` path
- [ ] fork bomb on execute of executable dazzlelink -- gone (HV.3)
- [ ] exit-code 0-on-failure -- gone (HV.7)

## Section 4: Monolith parity (~3 min)
- [ ] Spot-run `create`/`execute --mode info`/`rebase`/`update-config` against `python legacy/dazzlelink_monolith.py ...` and confirm equivalent behavior (the monolith now also prints the deprecation notice).

## What the automated tests DON'T cover
- Fresh-venv wheel install + console script (HV.1)
- Real symlink ops with privilege (copy/convert/mirror/export)
- The generated executable script running under a real shell + codepage
- Real `os.startfile`/`xdg-open` launch (tests mock it)
- Monolith parity by eye
- Packaging contents of the actual built artifacts

## Reporting issues found
Note section/step, shell, elevation, exact command + output. A fork-bomb, a corrupted `.dazzlelink`,
a broken wheel, or a non-zero-on-success exit code is a release blocker.
