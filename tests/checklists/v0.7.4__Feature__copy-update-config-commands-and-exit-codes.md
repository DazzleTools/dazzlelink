# Human Test Checklist: copy + update-config commands, and CLI exit codes (parity Commit 2a)

**Target version:** 0.7.4 (version TBD at commit -- patch per session cadence; minor 0.8.0 defensible since two commands are Added)
**Ships with commit:** TBD -- "feat: wire copy + update-config commands; propagate CLI exit codes"
**Companion automated tests:** 16 in `tests/test_cli_commands.py` (CLI import smoke, all-commands help, per-command help, update-config dry-run/real, copy error path) + 15 in `tests/test_executable_and_mode_precedence.py`

## What this is

The modular package was missing two commands the monolith had: **`copy`** (copy symlinks to a new
location) and **`update-config`** (batch-edit the config inside many `.dazzlelink` files). Both
operations already existed in `operations/` but were never wired to the CLI. This checklist verifies
they now work end-to-end and match the monolith. It also covers a behavior fix: `python -m dazzlelink`
previously **always exited 0**, even on error -- exit codes now propagate.

Mocks can't cover the parts that matter here: real symlink copying (privilege, structure preservation,
relative/absolute conversion), real `.dazzlelink` file mutation, and actual process exit codes.

## Prerequisites

1. Windows 10/11 or Linux/macOS, Python >= 3.10, editable install (`pip install -e .`).
2. **State isolation:** ALL operations in a `%TEMP%`/`/tmp` sandbox. Never run `copy`/`update-config`
   against real projects or your real `~/.dazzlelinkrc.json`. `update-config --config-level global`
   would touch the real rc file -- only test that with `--config-level file` (the default) unless you
   back up the rc file.
3. **Symlink privilege:** `copy` operates on real symlinks; creating them on Windows needs Developer
   Mode or an elevated shell. `copy` steps are flagged `[needs symlink privilege]`.

**Sandbox (PowerShell):**
```powershell
$env:DLT = "$env:TEMP\dl-2a"
Remove-Item -Recurse -Force $env:DLT -ErrorAction SilentlyContinue
New-Item -ItemType Directory -Force "$env:DLT\src", "$env:DLT\dst" | Out-Null
"payload" | Set-Content "$env:DLT\src\target.txt"
cd C:\code\dazzlelink
```

**POSIX:**
```bash
export DLT=/tmp/dl-2a
rm -rf "$DLT"; mkdir -p "$DLT/src" "$DLT/dst"
echo payload > "$DLT/src/target.txt"
cd /path/to/dazzlelink
```

## High-Value Verification (~5 min)

### HV.1 -- The two commands exist and are discoverable

- [ ] `python -m dazzlelink --help` lists both `copy` and `update-config` in the command list.
- [ ] `python -m dazzlelink copy --help` and `python -m dazzlelink update-config --help` both print
  usage (rc 0).
- [ ] **Why:** these were the two commands missing from the modular package vs the monolith.

### HV.2 -- update-config dry-run does NOT modify; real run does

- [ ] **Steps:**
  ```
  python -m dazzlelink create "<DLT>/src/target.txt" "<DLT>/a.dazzlelink"
  python -m dazzlelink create "<DLT>/src/target.txt" "<DLT>/b.dazzlelink"
  python -m dazzlelink update-config "<DLT>" --mode open --dry-run
  ```
  Inspect `a.dazzlelink` (PowerShell `Get-Content`, cmd `type`, POSIX `cat`) -- `default_mode` still `info`.
  Then:
  ```
  python -m dazzlelink update-config "<DLT>" --mode open
  ```
  Inspect again -- `default_mode` now `open` in both files.
- [ ] **Expected:** dry-run prints "Dry run - no changes were made" and "N files would be updated";
  real run prints "N files updated"; only the real run changes the files.
- [ ] **Why:** dry-run that silently mutates would be a data-integrity bug.

### HV.3 -- Exit codes propagate (the behavior fix)

- [ ] **Steps** (each line; check the exit status after):

  **PowerShell:**
  ```powershell
  python -m dazzlelink copy "$env:DLT\src\target.txt" "$env:DLT\dst"; "exit=$LASTEXITCODE"
  python -m dazzlelink update-config "$env:DLT" --mode open; "exit=$LASTEXITCODE"
  ```
  **cmd.exe:** append `& echo exit=%ERRORLEVEL%`
  **POSIX:** append `; echo "exit=$?"`
- [ ] **Expected:** a command that errors (e.g. copy with a non-symlink arg, or a not-found target)
  exits **non-zero**; a successful command exits **0**. Before this fix every invocation exited 0.
- [ ] **Why:** scripts and CI rely on exit codes; silent success-on-failure is a real trap.

### HV.4 -- copy a real symlink `[needs symlink privilege]`

- [ ] **Steps (PowerShell, elevated/Dev Mode):**
  ```powershell
  New-Item -ItemType SymbolicLink -Path "$env:DLT\src\link.txt" -Target "$env:DLT\src\target.txt" | Out-Null
  python -m dazzlelink copy "$env:DLT\src\link.txt" "$env:DLT\dst"
  Get-Item "$env:DLT\dst\link.txt" | Select-Object LinkType, Target
  ```
- [ ] **Expected:** prints "Copied 1 symlinks to ..."; the destination has a symlink pointing at the
  same target. If unprivileged, expect a clear error -- judge its quality, mark SKIP(privilege).

## Section 1: copy command (~5 min) `[needs symlink privilege]`

### 1.1 Copy a directory of symlinks (expansion)
- [ ] Make 2-3 symlinks under `<DLT>/src`, then `python -m dazzlelink copy "<DLT>/src" "<DLT>/dst"`.
- [ ] **Expected:** directory arg is expanded to its symlinks; all are copied; non-symlinks are skipped
  with a WARNING; count reported.

### 1.2 --relative / --absolute conversion
- [ ] `copy ... --relative` then inspect the destination link target -- it should be relative.
  `copy ... --absolute` -- absolute. Passing BOTH must error ("Cannot specify both") with rc 1.

### 1.3 --preserve-structure / --base-dir
- [ ] With `--preserve-structure` (and optionally `--base-dir`), nested symlinks land under a mirrored
  subtree in the destination, not flattened.

### 1.4 --no-verify
- [ ] `copy ... --no-verify` skips the post-copy verification step (faster; no verify output).

## Section 2: update-config command (~5 min)

### 2.1 --pattern and --recursive
- [ ] Create `.dazzlelink` files in `<DLT>` and a subdir. `update-config <DLT> --mode open` touches only
  the top level; `--recursive` reaches the subdir. `--pattern "a*.dazzlelink"` limits the matches.

### 2.2 --make-executable
- [ ] `update-config <DLT> --mode open --make-executable` -- updated files become executable scripts
  (the `#!`/`@echo` wrapper, per the v0.7.2 executable work). Verify one parses:
  `python -m py_compile <file>` (cross-platform).

### 2.3 Error reporting
- [ ] Point `update-config` at a directory with a malformed `.dazzlelink` -- the errors count is
  non-zero and each error lists path + reason; rc is non-zero.

## Section 3: Monolith parity spot-check (~3 min)
- [ ] Run the same `copy` and `update-config` invocations against
  `python legacy/dazzlelink_monolith.py ...` and confirm equivalent behavior/output. (The package
  should match the monolith for these commands.)
