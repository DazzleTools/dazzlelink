# Human Test Checklist: dazzlelink 0.10.0 -- portable cross-references

**Target version:** 0.10.0
**Ships with commit:** `2e11b0f` feat: portable cross-references -- delegate paths to the stack
**Companion automated tests:** dazzlelink 58 (`tests/test_portable_paths.py` +6 new), dazzle-linklib 89 (`tests/test_locators_population.py` +19), unctools 62 (`tests/test_path_variants_v030.py` +8).

## What this is

0.10.0 delivers issues #13 + #24: records carry the portable path family at create (relative / UNC / drive / subst expansion) and `execute` performs **live re-resolution** against the executing machine's current mappings. The tool's private `UNCAdapter` is deleted (stack V2) — representation building now flows tool → dazzle-linklib → unctools. This checklist covers what the mocks and single-machine tests can't: **real cross-machine resolution** (different drive letters, UNC-only reach, synced trees), real `net use`/`subst` environments, and the feel of the new failure diagnostics.

## Planning lineage

**Public**: `CHANGELOG.md` [0.10.0]; dazzle-linklib `docs/api.md` (locator population + live re-resolution); issues #12, #13, #24.
**Project-private** (not in public git history, for project maintainers): the collabN-local consultation (`2026-07-29__20-10-35` through `20-37-40` DISCUSS files) and the Rnd4 final assessment (acceptance checks AC-A..AC-I); `2026-07-29__19-52-49__dev-workflow-process__aktuldjr-drift-remediation.md`.

## Prerequisites

1. Windows machine with the stack installed: `pip install dazzlelink` (>= 0.10.0) — or editable installs of all four repos.
2. For the cross-machine sections: a second machine (or the aktuldjr setup: `net use` mapped drives, e.g. `D: → \\Aktuldjr\d`).
3. State isolation: work only in scratch directories; `subst` letters are removed after each test (`subst X: /d`).

### Reset between sections
  **cmd.exe**: `rmdir /s /q %TEMP%\dz10 & mkdir %TEMP%\dz10`
  **PowerShell**: `Remove-Item -Recurse -Force $env:TEMP\dz10; New-Item -ItemType Directory $env:TEMP\dz10`
  **POSIX**: `rm -rf /tmp/dz10 && mkdir /tmp/dz10`

## High-Value Verification (~6 minutes)

### HV.1 — All three suites green

- [ ] **Steps:** `python -m pytest -q --no-cov` in `C:\code\dazzlelink`; `python -m pytest -q` in `C:\code\dazzle-linklib`; same in `C:\code\UNCtools\local`.
- [ ] **Expected:** 58 / 89 / 62 passed (skips for privilege-gated tests are fine).
- [ ] **Why this matters:** the regression floor across the whole train.

### HV.2 — Create writes the path family

- [ ] **Steps:** in a scratch dir: create a file, `dazzlelink create --config-level file <file> <file>.dazzlelink`, then inspect the JSON (`python -m json.tool`).
- [ ] **Expected:** `target_representations` contains `original_path` AND `relative_path`; on a `net use` mapped drive also `unc_path`/`drive_path`; on a subst drive also `subst_path` (the EXPANDED real path).
- [ ] **Why this matters:** this is the exact field-report gap ("only original_path was written").

### HV.3 — The moved-tree scenario (the #13 story)

- [ ] **Steps:** create target + record side-by-side in `treeA`; copy the tree to `treeB`; delete `treeA`; from an UNRELATED cwd run `dazzlelink execute --mode open treeB\<name>.dazzlelink`.
- [ ] **Expected:** opens `treeB`'s copy (relative resolution anchored at the record's directory, not CWD, not the dead absolute).
- [ ] **Why this matters:** the original Taleb-library failure from #13, and the Resilio use case from the aktuldjr report.

### HV.4 — Subst alias death

- [ ] **Steps:** `subst Q: <scratch>`; create a record for `Q:\<file>`; `subst Q: /d`; execute the record.
- [ ] **Expected:** opens the real path (stored `subst_path` expansion) even though `Q:` no longer exists.

### HV.5 — Failure output lists the tried candidates

- [ ] **Steps:** move a record away from its tree and delete its target; execute it.
- [ ] **Expected:** error reads `Target not found. Tried (in resolution order):` followed by every candidate path, one per line — not the old three-line summary.

### HV.6 — Removed API is really gone (and documented)

- [ ] **Steps:** `python -c "import dazzlelink; dazzlelink.UNCAdapter"` → AttributeError; CHANGELOG [0.10.0] Removed section names a replacement for each symbol.

## Section 1: Cross-machine resolution (#24's real acceptance test — needs machine B)

This is the part no single-machine automation covers. The aktuldjr environment (`net use` `D: → \\Aktuldjr\d`) is the canonical setup.

### 1.1 Drive-letter record resolves via UNC on machine B

- [ ] **Steps:** on machine A (drive `D:` mapped to a share): create a record whose target is `D:\...\file`. Carry the record to machine B that reaches the same share **only by UNC** (no drive mapping). Execute.
- [ ] **Expected:** resolves — live re-resolution converts the stored drive form to UNC via machine B's view (or uses the stored `unc_path`). This is #24 AC (a).

### 1.2 Different letter on machine B

- [ ] **Steps:** same record; machine B maps the same share under a DIFFERENT letter (e.g. `net use E: \\Aktuldjr\d`). Ideally also block direct UNC (or just verify which candidate won by the opened path).
- [ ] **Expected:** resolves via machine B's current mapping — the stored literal `D:` form is dead, the UNC form re-localizes to `E:`. This is #24 AC (b), the case that was impossible before 0.10.0.

### 1.3 Synced tree across peers (Resilio / MoonshotAI case)

- [ ] **Steps:** create a record inside a synced tree on peer A (`_Models\Kimi-K3` → `_Github\Kimi-K3` pattern); let it sync; execute on peer B where the tree lives under a different root.
- [ ] **Expected:** resolves via relative. (The record itself syncs as a plain file — that's the point.)

## Section 2: Ordering + regression feel (~4 min)

### 2.1 Relative beats a stale absolute

- [ ] **Steps:** create record; move the whole tree; recreate a DIFFERENT file at the original absolute path... actually verify the opposite: absolute is tried FIRST when it exists. Then delete the absolute target and confirm relative wins next.
- [ ] **Expected:** `absolute → relative → unc → drive → subst` order observable via which file opens / the tried-list on failure.

### 2.2 Old records still execute (backward compat)

- [ ] **Steps:** execute a pre-0.10.0 record (e.g. `examples/Roddenberry-Saturn.lnk.png.dazzlelink` for `--mode info`; any 0.9.x-created record for open).
- [ ] **Expected:** identical behavior; records without the new keys just skip those candidates.

### 2.3 Polyglot executable record

- [ ] **Steps:** `dazzlelink create --executable`; double-click it (file association) AND `execute --mode info` it.
- [ ] **Expected:** both work; no fork-bomb (the execute path never shell-executes the script).

## Section 3: Performance + POSIX (~3 min)

### 3.1 Execute latency feel

- [ ] **Steps:** time `dazzlelink execute --mode open` on a local record (`Measure-Command` / `time`).
- [ ] **Expected:** no perceptible regression — the mapping enumeration is one-shot per invocation (subst) + cached (net use). If it feels slow on a machine with a hung network drive, that's the ledgered `--no-reresolve` trigger — report it.

### 3.2 POSIX create/execute

- [ ] **Steps:** on Linux/macOS/WSL: create + execute a record.
- [ ] **Expected:** family = original + relative only; no subprocess spawns; resolution works.

## What the automated tests DON'T cover

- **True cross-machine resolution** (Section 1) — the linklib tests simulate machine B with injected fake variants; only real machines prove the unctools enumeration end-to-end. **Section 1 on aktuldjr is the release-blocking human check.**
- Network-drive edge states: hung/slow shares at enumeration time, DFS, third-party providers (the WNet enrichment path).
- Double-click execution via the Windows file association (HV/2.3 partially).
- Error-message readability judgment (HV.5 shows it; a human judges it).

## Reporting issues found

Section+step, exact command, full output, the record JSON (sanitized). File against DazzleTools/dazzlelink referencing this checklist; the `--no-reresolve` escape hatch and the wrong-file-via-variant hazard both have ledgered reopen triggers in the Rnd4 assessment — cite them.

## Cleanup

`dz safedel` the scratch dirs; `subst <X>: /d` any leftover aliases; `net use E: /delete` any test mappings.
