## Bug found

### Bug #1 -- apply_record_metadata writes timestamps to target, not link (Windows)

**Severity:** Medium. Symlink creation always succeeds. File attributes (hidden/readonly) correctly land on the link. Timestamp application follows the symlink to the target, silently modifying the target's mtime/atime instead of the link's own reparse-point timestamps.

**Contract violation:** `apply_record_metadata` docstring states "acts on the link, not the target." This is false for timestamps on Windows.

**Root cause:** `fk.apply_file_metadata` calls `os.utime(path_obj, (accessed, modified))` without `follow_symlinks=False`. On Windows, `os.utime` follows symlinks by default. The attributes code path uses `win32api.SetFileAttributes`, which correctly operates on the NTFS reparse point (the link itself).

**Minimal repro:**

```python
import os, time, tempfile
from pathlib import Path
from dazzle_linklib import DazzleLinkData, apply_record_metadata

d = Path(tempfile.gettempdir()) / "bug1_repro"
d.mkdir(exist_ok=True)
target = d / "target.dat"
link = d / "link.lnk.dat"
target.write_bytes(b"test")
os.symlink(str(target), str(link))

modified_ts = time.time() - 9999
rec = DazzleLinkData()
rec.set_target_path(str(target))
rec.set_original_path(str(link))
rec.set_link_timestamps(created=modified_ts, modified=modified_ts, accessed=modified_ts)

target_mtime_before = os.lstat(str(target)).st_mtime
apply_record_metadata(rec, str(link), timestamp_strategy="symlink")

print("target mtime changed:", abs(os.lstat(str(target)).st_mtime - target_mtime_before))  # ~9999
print("link lstat mtime changed:", abs(os.lstat(str(link)).st_mtime - target_mtime_before))  # ~0
# target mtime changed: ~9999.0   <- BUG: target was modified
# link lstat mtime changed: ~0    <- link's own mtime was not set
```

**Fix location:** `C:\Python312\Lib\site-packages\dazzle_filekit\metadata.py`, line 224.
Change: `os.utime(path_obj, (timestamps['accessed'], timestamps['modified']))` to use `follow_symlinks=False`.
However, `os.utime` with `follow_symlinks=False` is only supported on platforms where `os.supports_follow_symlinks` includes `os.utime`. On Windows with Python 3.12, this may require using the Win32 `SetFileTime` API on the link's handle opened with `FILE_FLAG_OPEN_REPARSE_POINT`. This is a filekit-level fix; the fix should live in `dazzle-filekit`, not `dazzle-linklib`.

**Impact on 0.9.1 users:** Any `dazzlelink import` with `--timestamp-strategy symlink/target/preserve-all` silently modifies the target file's timestamps. For read-only targets this may fail silently. For write-accessible targets, the target's access record is modified unexpectedly. The link's lstat mtime stays at creation time regardless of strategy.
