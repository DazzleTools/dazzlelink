## Detailed Evidence for FAIL / PRE-EXISTING / REVIEW Items

### FAIL: 5.1 -- Monolith fallback path in file-association scripts is stale

**Both scripts** check the wrong path for the legacy monolith:

**PS1 (line 34):**
```powershell
$dazzleLinkScript = Join-Path (Split-Path -Parent $scriptDir) "dazzlelink.py"
# Resolves to: C:\code\dazzlelink\dazzlelink.py  -- DOES NOT EXIST
```

**BAT (line 82):**
```cmd
set DAZZLELINK_SCRIPT=%SCRIPT_DIR%..\dazzlelink.py
:: Resolves to: C:\code\dazzlelink\dazzlelink.py  -- DOES NOT EXIST
```

The correct path after the restructure is `legacy\dazzlelink_monolith.py`. On machines where `python -m dazzlelink` works (pip-installed), this path is never reached, so the bug is silent. On bare-clone or non-pip environments, the fallback silently fails to find the monolith. Both scripts have graceful "not found" error handling that catches this case, so it won't crash -- but the fallback protection is now broken.

**Classification:** FAIL (regression of this specific restructure -- moving `dazzlelink.py` to `legacy/dazzlelink_monolith.py` without updating the script fallback paths). These scripts have staged-but-unstaged working-tree changes, suggesting they WERE being updated -- confirm those unstaged edits address this issue.

**Fix:** In both scripts, change the fallback check from `dazzlelink.py` to `legacy\dazzlelink_monolith.py`.
